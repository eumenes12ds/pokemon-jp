# Pokémon identity registry

Release `v2026.9.24.1`. `runtime.js` and the generator are CC0-1.0; CSV data retains the BSD notice in `sources/LICENSE`. Pokémon names and artwork remain the property of their respective owners.

`catalog.json` is the auditable table; `catalog.js` is its generated browser module. The MVU schema and inline HUD import the same resolver. PokeAPI species numbers and form IDs, canonical English form identifiers, Japanese species/form labels, and exact normal/shiny/female asset paths remain separate fields. Default species aliases select the default form; filename aliases can select legacy forms. Explicit full form identifiers take priority over contradictory old image fields. Player nicknames and eggs are preserved. Ambiguous aliases are rejected. Unknown IDs and unsupported images use the owned placeholder and never issue external requests.

Sources: PokeAPI/pokeapi `2b9ea590fcc62a1bce2534835e9d5d1b234a2976`; previously archived Showdown sprites; PokeAPI/sprites `a13b1f4ccd77f35fd1370d2db5f0051221e9683f` for exact static fallback images. `sources/provenance.json` and `media-manifest.json` contain original URLs, checksums and upstream Git blob IDs. The Japanese names for Pidove and Mr. Mime were additionally checked against https://zukan.pokemon.co.jp/detail/0519 and https://zukan.pokemon.co.jp/detail/0122 . Other names follow the pinned community dataset; this is not an official Pokémon database release.

Coverage: 1,025 species / 1,579 API form records. All default species have normal and shiny assets. Eight Koraidon/Miraidon transport postures have no independent archived image and explicitly use the placeholder; battle forms have assets. Cosmetic forms with identical appearance share an explicitly selected image. Species and forms are distinct from nicknames, shininess, or gender-specific sprites.

Run `python registry/build.py` from the repository root to rebuild from the pinned source snapshots. No network call is made by the browser to PokeAPI; the builder downloads only missing archived fallback PNGs and checks upstream Git blob hashes. Selective card worldbook entries are generated from this same catalog; card prompts and private user data are not stored in this repository.
